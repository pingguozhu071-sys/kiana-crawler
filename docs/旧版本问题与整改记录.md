## 1. 基线与推进范围

- **接手基线**：`v2.10.3.0`。仓库首个提交即"接手前快照"，**不包含接手之后的任何改动**。
- **本工程不是从零构建**：它承接了一个既有的单机采集器，并在其上大幅推进 —— 把"能跑的脚本集合"改造成"有并发语义、有安全边界、有质量门禁、有文档体系的工程"。
- 当前规模（实测口径见第 5 节）：引擎 **71 个模块 / 27,620 行**；桌面界面 **3,652 行**；测试 **110 个文件 / 约 1,490 个用例**；发版门禁 **14 项**。
- 内部自查（含安全审计）**不构成任何形式的第三方认证**。

## 2. 基线里已存在的问题（按性质分组）

### 2.1 结果不可信 —— **假成功**

这类问题的共同形态是：**程序报告成功，但产物不是它说的那个东西**。它们比崩溃危险，因为使用者不会去查。

| 现象 | 根因 | 代价 | 处置 |
|---|---|---|---|
| 日志宣称"检测到会员凭据 → 强制最高画质"，实际只拿到 480P | 探测只检查**文件名里有没有站点关键词**，从未向服务端核验登录态 | 使用者以为拿到了高清 | 改为**真验证登录态**：向服务端探测并按返回码如实报告"已失效/本次只能拿到 480P 及以下" |
| 下载失败时，兜底把**上一次下好的视频**当本次成果 | 兜底逻辑取"目录里第一个真视频"，而不是"本次新出现的" | 记账指向别人的文件；日志反复刷同一个旧文件名 | 下载前拍**目录快照**，兜底只认"本次新增"的文件；并加产物形态校验 |
| 凭据文件路径失效，被含糊成"未检测到" | 只判断"有没有配"，不判断"配的那个还在不在" | 使用者以为配好了 | 路径失效时**点名报警**，并区分"没配"与"配了但文件不存在" |
| 加密媒体流取不到密钥时，仍把**未解密的密文**合并成 `.mp4` 并报成功 | "取到密钥才解密"没有 else 分支，合并与返回成功无条件执行 | 产出一个完全无法播放的文件，却记成完成并带一个"看起来合理"的体积 | 取不到密钥即**拒绝合并并如实失败** —— 宁可失败，也不产出一个放不了的文件 |
| 某依赖库的 API 漂移被**静默吞掉** | 调用点异常被降到 debug 级，连"未安装"提示一并消失 | 功能莫名消失且无线索 | 恢复显式告警，并把"版本漂移"与"未安装"分开报 |

### 2.2 结果不可信 —— **假失败**

| 现象 | 根因 | 代价 | 处置 |
|---|---|---|---|
| 进度条显示 `fail=19`，而日志里**一条错误都没有** | "达到使用者设定的页数上限"被记成 `failed` | 排查者被这个假失败数带偏两轮 | 上限跳过记 **`skipped`**，与 `failed` 分开显示；`failed` 不得再包含跳过 |

> 关键细节：队列那边**仍必须**把任务移出待处理（主循环的退出条件是"待处理 + 重试 == 0"）。**移除动作是对的，标签是错的** —— 修复落在报告层。

### 2.3 静默失效 —— **东西建好了，但从没接线 / 从没跑过**

这是本工程最稳定的一类缺陷：代码看着完整、测试看着通过，而它在生产路径上**一次都没执行过**。

| 现象 | 根因 | 代价 | 处置 |
|---|---|---|---|
| 整条 55 维浏览器反检测注入链**从第一天起就没有执行过** | 两个缺陷**叠加**：① 生产优先使用的驱动改写了 init script 注册路径，导致脚本下发后永不执行；② 注入脚本是模板字符串，转义被求值成真实换行 ⇒ JS 语法错误。**任一单独存在，整条链都是死的** | "防检测"这一整块地基实际不存在，多次被风控拦截 | 加**注入通道自证探针**（真的下发一段标记脚本、读出它是否执行），实测不通则**自动回退**到能用的通道；真机复跑自证告警 5 → 0 |
| 一处"环境自检"是**死代码** | 它读一个从未被赋值的属性，异常被函数末尾的空 `except` 吞掉 | 连带两条启动提示从未弹出；且每次点"开始"还会在主线程同步联网探测，**界面最长假死 10 秒** | 连同那段死代码一起删除，并把假死路径去掉 |
| 打包版的"隐私扫描"会**再弹一个程序窗口**，并且那个扫描脚本在管道下因编码必崩 | 打包后 `sys.executable` 指向界面程序自身，且脚本从未以管道方式验证过 ⇒ **这个按钮从来没有成功过** | 用户按了没反应，还会被弹第二个窗口 | 扫描脚本内部统一输出编码；打包版**如实拒绝并说明原因**，绝不弹出第二个窗口 |
| 按站身份池：开关能点、状态说"库里没有身份"，**却无处可加** | 导入入口根本不存在；且**存储用的键与查询用的键不是同一个**（于是永远取不到） | 功能等于不存在 | 补上导入入口（界面 + 命令行），并把键的归一化收敛到**唯一实现** |
| "检测到验证码挑战"**全是误报** | 只匹配页面 HTML 里的一个**裸字符串**，而目标站点每个页面骨架都含它 | 真机 17 次检测、页面上零元素 ⇒ 白起十几次浏览器，**并把排查引向错误方向两轮** | 改成**结构化判定**（只认真实 DOM 元素，脚本被加载 ≠ 挑战在运行）；真机复跑 17 → 0 |

### 2.4 同一能力多份实现 / 同一事实多个说法

| 现象 | 根因 | 处置 |
|---|---|---|
| 凭据文件解析在 **9 处**各写一份，**全部漏掉 `#HttpOnly_` 前缀** | 没有唯一入口 | 收敛到**唯一解析模块**，并把带前缀的行按数据而非注释处理（修复前会话凭据被静默丢弃） |
| 域名匹配用**子串**判断（`d in host`），凭据会被注入到仿冒域名 | 用字符串包含冒充域名归属 | 删除该分支，改为逐级后缀匹配，并加**反向验证**钉死 |
| 防盗链 Referer **三种做法**，其中两种正好命中会被拒绝的形态 | 三次独立实现 | 收敛到唯一实现，并把"别处要判基址一律调它"写进注释 |
| 域名提取**三份实现、两种不一致**（裸域名返回空串 / 畸形输入抛异常） | 同上 | 收敛到唯一实现 |
| **文档自相矛盾**：同一份文档里两个引擎行数、两个标签数、两个覆盖率 | 数字靠手抄 | 引入**数字同步工具**（实测后写回文档）+ 文档数字守卫测试 |

### 2.5 稳定性与资源

| 现象 | 根因 | 处置 |
|---|---|---|
| 单个页面挂起会**冻住整批** | 阻塞调用出现在主线程/事件循环 | 阻塞调用一律搬到线程池；单页看门狗可配置、可显式关闭 |
| 收尾阶段**白烧 150 秒** | 被放弃的任务**不改终态** ⇒ 队列永远等不到空 | 放弃即记终态（`skipped`）并把它移出待处理；**本轮在视频路径上补修了同一形状** |
| 队列数据库文件**从构造起被锁到进程结束** | 用 `with` 语句当成"关闭连接"，而它只管事务、不管关闭；连接存在引用环，只有垃圾回收才真正释放 | 显式关闭连接（实测：修复前文件删不掉、修复后可删） |
| 若干工具脚本**默认写真实数据根** | 构造界面对象本身就有写路径（启动迁移钩子） | 默认重定向到临时目录，需显式开关才写真实数据根 |

## 3. 仍然存在、已登记的（如实列出）

以下问题**已知、已定性、尚未修改**，原因逐条写明。把它们写出来是为了让使用者能自己判断风险面，而不是让它们"悄悄消失"。

| 问题 | 性质 | 为什么不改 |
|---|---|---|
| 每域视频上限的**计数口径**把"从未移动"的行也算进去 | 上限一旦成立就**永久成立**，该域后续视频都被跳过 | 改它会**改变实际下载数量**，属产品决策（是"最多**下** N 个"还是"最多**试** N 个"） |
| 复跑同一任务时，**已完成的记录会被打回待处理** | 会重下一遍，并让收尾阶段每轮白烧 150 秒 | 那条"重置"是**为修一个更严重的老缺陷而刻意加的**（否则误标完成后视频永远不再下载），仓促改会把老缺陷请回来 |
| 上限判据使用**只增不减**的计数器，而队列库跨轮复用 | 第二轮起上限可能先于本轮任务成立 | 取决于 `max_pages` 的语义定位（"本次任务"还是"该任务目录累计"），需产品决策 |
| 下载器里"找本次新产物"的兜底是**死代码**（快照取值前后相邻，差集恒为空） | 该救援层从未生效；"下载成功但被判失败"时产物会成为孤儿 | 牵动记账与产物落点，需真机样本验证 |
| 加密媒体流的**分片成功只看 HTTP 状态码** | 空响应体/被截断/软错误页都会被当成成功分片 | 需真实 CDN 样本才能定验收判据 |
| 完整性校验的开关握在"探测"手里，探测失败时是**静默降级** | 服务端不报长度时可能把截断传输当成功 | 需真机/特定服务端样本 |
| 私有分发的第三方组件与便携性 | 便携数据根使用了按用户/按机器绑定的加密，换机解不开 | 属安全强度取舍：改成"换机可解"等于**降低加密强度** |

## 4. 从这一系列缺陷里得出的四条纪律

这四条不是口号 —— 每一条都对应上面某个真实缺陷，且都写进了本工程的测试或门禁。

1. **判据必须查结构，不许查文本。**
   断言"日志里出现了某句话"、断言"源码里有某个子串"，都会在**措辞被改写时静默失效**。本工程真发生过一次：一条测试连续红了两轮，看起来像反检测回归，实际是它断言的**那句日志文案已被重写**。接线断言一律用语法树，行为断言一律跑真实路径。

2. **"没有告警"不等于"通过"。**
   正面结论必须落到**可断言的状态**上（例如"自证通过"置一个可读的标志），而不是靠"日志里没看到异常"倒推 —— 上面那个"注入链从没执行过"的缺陷，正是靠"没告警"藏了很久。

3. **复核命令必须真能跑出它上面的数字。**
   白皮书附录里曾有一条复核指引，实跑得到 9，而正文写 8；另有一条数字在代码里**找不到可枚举的出处**。凡是写进文档的量化断言，都必须配一条能现场跑出该数字的命令，否则删掉它而不是加注释。

4. **计数口径必须与被移动的状态同源。**
   "计数包含了永远不会移动的行"会让条件**一旦成立就永久成立**。本工程在页面侧与视频侧各踩过一次，其中一次的表现是"每次撞上限都白烧 150 秒"。

**以及一条横向的**：同一能力**只允许一份实现**。上面第 2.4 节每一个缺陷都是"同一件事写了两遍以上"的直接后果；本工程现在用自动化守卫来阻断新增分叉。

## 5. 如何复核本文档的断言

以下命令在仓库任意位置（Git Bash / WSL / PowerShell）都可直接执行，输出即上文数字。

```bash
# 引擎规模：模块数 / 总行数
ls kiana_vnext_plus/*.py | wc -l
wc -l kiana_vnext_plus/*.py | tail -1

# 桌面界面行数
wc -l launcher_v9.py

# 测试规模：测试函数数（另有少量参数化，收集数略高于此）
grep -rhE '^[[:space:]]*(async )?def test_' tests | wc -l

# 规则资产：声明式规则文件总数（其中 2 个是模板）
ls rules/sites/*.yaml | wc -l

# 发版门禁项数
grep -c 'checks.append((' tools/release_check.py

# 静态基线锁定值
grep -n 'RUFF_MAX, MYPY_MAX' tools/release_check.py
grep -n 'TOOLS_F_MAX' tools/release_check.py

# 队列库 schema 版本
grep -n 'SCHEMA_VERSION = ' kiana_vnext_plus/frontier.py

# 跑一遍全量测试（离线，约 6 分钟）
python -m pytest tests -q
```

> 若某条命令在这里跑不出上文对应的数字，那是**本文档的缺陷**，请以命令输出为准并提 issue —— 第 4 节第 3 条纪律就是为这种情况立的。
