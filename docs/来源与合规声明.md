## 二、发版依赖许可（requirements.txt 全 pin 已审计）

**第三方库依赖含 2 个 GPLv3 组件**，随安装包一同分发：

| 依赖 | 许可 | 说明 |
|---|---|---|
| `PySide6-Fluent-Widgets`（qfluentwidgets） | **GPL-3.0** | GUI 壳主入口 |
| `bgutil-ytdlp-pot-provider` | **GPL-3.0** | YouTube PO Token 组件 |

`PySide6` 为 LGPL/GPL 三许可（分发时按 GPL 侧口径）。**本工程整体以 GPL-3.0 发布**（见 `LICENSE` 与
根目录 `README.md`「License & provenance」一节）—— 这不是偏好，而是与上述 GPLv3 组件一致分发所必需的许可。

除上述组件外，其余 pin 死的依赖均为 MIT / BSD / PSF / Apache-2.0 / Unlicense 类许可（PyPI 元数据核对）；
其中 `gmssl==3.2.2` 为 BSD（SM3 哈希原语），`curl_cffi` 为 MIT，
`yt-dlp` 本体为 Unlicense（上游另声明：其 PyInstaller 发行二进制因捆绑代码而整体按 GPLv3+ 分发）。

> **口径边界**：本节讨论的是**第三方库依赖**的许可；本工程**自有代码**的 copyleft 残留见第一节，
> 结论是 0。两条陈述互不矛盾，也不再把「无 GPL」套用到整仓层面。

## 三、红线与流程

1. 后续引入任何第三方代码：先查许可 → GPL/AGPL/LGPL 类**一律不引入**（或仅参考语义+全重写并登记本表）。
   本工程整体虽以 GPL-3.0 发布，本条约束针对的是**引入外部代码的准入**，与之不冲突；
2. 借鉴实现：注释必须写明"参考 XX 的算法/模式，实现为本工程重写"；
3. 每发版前跑 `tools/release_check.py`（已内置密钥扫描；本表人工复核一遍）。
