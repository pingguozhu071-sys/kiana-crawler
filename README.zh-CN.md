## 概述

面向 Windows 的**单机采集引擎**：核心为自包含的 asyncio 爬虫内核，PySide6 桌面界面作为控制层。

设计围绕四个核心问题展开，而非站点覆盖面：

| | 问题 | 方案 |
|---|---|---|
| **抓取** | 站点以 TLS 指纹、JS 挑战、行为检测实施拦截 | 五级回退：协议通道 → 隐身通道 → TLS 切换 → 真浏览器 → 直连 |
| **解析** | 各站点页面结构差异显著 | 通用正文抽取 + 声明式站点规则 + 页面内嵌 JSON 解析 |
| **数据质量** | 重复内容、空壳页、隐私信息混入产物 | 内容指纹去重 + 质量评分闸 + 三层脱敏 |
| **稳定性** | 数十路并发、连续运行数小时、单页可能挂起 | 租约 + CAS 一致性 + 单页看门狗 + 令牌桶限速 + 断点续传 |

## 技术亮点

每项技术要点均按统一的四段结构描述：**问题 → 实现 → 关键数据 → 所在模块**。

### ① 五级回退引擎：内容可达性

> **问题**：站点的内容拦截方式各异：部分直接返回内容，部分校验 TLS 握手指纹，部分需真实执行 JavaScript 后才渲染正文。单一策略无法同时覆盖这三类。

- **实现**：按代价由低到高排布五级 —— 协议通道（TLS 指纹模拟）→ 隐身通道 → TLS 切换 → 真浏览器 → 直连。前一级失败或遇到挑战时自动升级至下一级；低成本通道可获取内容时不启动浏览器。
- **关键数据**：5 级回退 · 20–50 路协程并发 · 浏览器渲染设有独立预算上限（防止浏览器进程过度启动）
- **所在模块**：`engine_router.py` 主调度 · `protocol_engine.py` 协议通道 · `solver_engine.py` 浏览器通道

### ② 平台解析器：媒体直链提取

> **问题**：媒体站点的播放地址封装于页面内嵌 JSON 中并带时效签名；直接交由通用下载器处理，通常无法获得最高画质。

- **实现**：**优先读取页面已有的数据**（`window.__INITIAL_STATE__` / JSON-LD），而非直接构造请求参数。四个平台各自具有独立解析器，产物统一收敛到同一套 schema（`MediaItem`：source / media_id / kind / streams / images / method），上层只读取单一字段。从页面状态提取出的 URL 在使用前必经 SSRF 闸复检。
- **关键数据**：4 个平台解析器（抖音 / 小红书 / 快手 / 网易云）· 统一 schema 收敛 · 每条提取出的 URL 均复检
- **所在模块**：`media_schema.py` 统一 schema · `*_resolver.py` 各平台解析器 · `universal_downloader.py` 表驱动分派

### ③ 租约 + CAS：精确一次处理

> **问题**：两类经典并发故障 —— 同一页被两个协程同时处理（重复导出），或结果完成后被其他 worker 抢先认领（状态损坏）。

- **实现**：认领任务时写入租约（`leased_at` / `lease_expires`），以 60 秒心跳续约；**结果落盘前必须先通过一次 CAS**（比较交换），失败则不写入任何数据。看门狗与失败路径均带"不覆盖已完成"守卫。
- **关键数据**：租约 60 秒心跳 · 看门狗默认 300 秒（可配置、可关闭）· CAS 三态（成功 / 失败 / 数据库故障）
- **所在模块**：`frontier.py` 队列与 CAS · `page_processor.py` 单页流水线

### ④ 看门狗与两级限速：运行稳定性

> **问题**：单页挂起会拖累整批任务；限速实现不当会演变为永不终止的重试风暴。

- **实现**：单页超过超时上限即终止并标记重试，不影响同批其他页面。限速为全局 + 按域**两级令牌桶**。被限流**不消耗重试次数** —— 使用独立计数器与独立的死信阈值，主循环的退出条件因此能够满足。
- **关键数据**：看门狗 **300 秒**（正常单页 < 60 秒，预留 5 倍余量）· 每域并发 **20** · `Retry-After` 上限 **300 秒**
- **所在模块**：`crawler.py` 看门狗 · `rate_limiter.py` 令牌桶 · `concurrency.py` 三级仲裁

### ⑤ 断点续传且不重编码

> **问题**：大文件下载中断后不应从零开始；重编码则会破坏原始画质。

- **实现**：先探测总大小与 Range 支持情况 → 流式写入 `.part` 文件 → 自精确字节偏移续传 → 按字节数自校验 → **原子改名**，下游不会见到不完整的文件。视频仅做字节级传输、不重编码；音频通道开启时音频转 MP3。服务端不支持 Range 时，作废旧 `.part` 并重新下载，而非拼接出损坏文件。
- **关键数据**：分片校验 + 原子落盘 · 支持 m3u8 分片与 AES-128 解密 · ffmpeg 仅用于**合并**，不用于重编码
- **所在模块**：`universal_downloader.py` · `m3u8_downloader.py` · `media_downloader.py`

### ⑥ 逐跳 SSRF 闸

> **问题**：**仅在入口校验 URL 是不够的。** 一个外部图片地址可能返回 302 重定向至内网地址，底层 HTTP 库会自动跟随 —— **内网返回的内容被当作普通图片写入磁盘。** 已在开发机上以两个回环服务实测复现。

- **实现**：所有出网取流统一经由共享原语 —— 入口校验、关闭自动重定向、随后**逐跳跟随并复检落点**。主机名先做规范化（IPv6 zone id 与 FQDN 尾点均曾被用于绕过黑名单）。私网判定覆盖标准库未涵盖的地址段。DNS 判定结果有效期 90 秒，用于阻断"先解析至公网、再改指内网"的 rebinding 手法。
- **关键数据**：重定向上限 **10 跳** · DNS 判定 TTL **90 秒** · 覆盖 25 种私网形态 · 十进制 / 十六进制 / 八进制 IP 变体均正确处理
- **所在模块**：`url_utils.py`（全仓最高扇入模块）· 所有下载与发现通道

### ⑦ 三层脱敏及其明确边界

> **问题**：手机号、邮箱、URL 中的 token 泄漏进产物会构成实际风险。**脱敏也有边界** —— 作用位置错误会直接破坏功能。

- **实现**：三层 —— 日志层（过滤器挂载于 **handler**；挂载到 root logger 上不会产生任何效果）、旁路层（print 桥、GUI 日志、异常回显）、产物层（导出副本按整条记录脱敏）。
  **排除项是显式的**：任务队列中的 URL 是*后续仍需再次请求*的凭据 —— 抹除签名参数将导致续爬直接 403。该推理已写入代码注释，防止后续维护者无意破坏。
- **关键数据**：脱敏 URL 敏感参数 **19 类** · 手机号 / 邮箱 / IP · 记录级递归至 6 层
- **所在模块**：`sanitizer.py` · `config.py` 挂载装配 · `page_processor.py` 导出副本

### ⑧ 十项发版门禁

> **问题**：单人维护的工程，发布出问题的常见原因是某个假设未经验证。

- **实现**：单条命令运行十项检查，**任一项失败即禁止发布**：版本四件套一致性 · Git 工作区干净 · 全量测试 · 静态检查（基线锁定，只降不升）· 依赖漏洞审计 · 密钥泄漏扫描 · 凭据卫生 · 规则与资产完整性 · 多线实站回归 · 构建面自检。
- **关键数据**：**10 项门禁** · **675 个离线用例** · 静态基线锁定为实测值（只允许下降）
- **所在模块**：`tools/release_check.py` · `.github/workflows/ci.yml` · `tests/`

## 架构

```
launcher_v9.py          GUI 入口（五页：首页 / 日志 / 数据 / 任务 / 设置）
  └ launcher_v8.py      仅 4 个有效符号（引擎桥、日志双桥、配置路径、密钥存取）
run_crawler.py          命令行入口 —— 同时也是 GUI 的"进程内引擎"
  └ crawler.py          引擎装配（7 个 _init_* 为装配清单，run() 为主循环）
      ├ engine_router.py      五级回退调度
      ├ page_processor.py     单页流水线
      ├ frontier.py           SQLite 队列（租约 / CAS / 迁移）
      └ url_utils.py          安全原语（全仓最高扇入）
```

**单页处理流程**（17 步）：

```
创建任务目录 → 种子分流 → 入队 → 批量认领（租约）→ 确定出口与并发名额 → 心跳
  → 缓存命中判定 → 五级路由 → 解析炸弹防护 → 脱敏 → 去重 → 质量闸
  → CAS 认领 → 持久化/导出 → 媒体入队 → 出链发现 → 统计
```

**运行形态**：单进程 + asyncio 协程；线程仅用于承载阻塞调用，**不使用多进程**。引擎**不是子进程** —— GUI 在守护线程中运行独立事件循环，进程内直接驱动爬虫，`print` 与 `logging` 双路桥接回界面。

## 快速开始

**环境**：Windows 10/11 x64 · Python ≥ 3.11

```bash
# 1. 安装依赖（运行时 + 开发，版本均已锁定）
pip install -r kiana_vnext_plus/requirements.txt
pip install -r requirements-dev.txt

# 2. 启动桌面界面
python launcher_v9.py

# 3. 或使用命令行
python run_crawler.py "https://example.com" -d 0 -m 1 -o ./out
python run_crawler.py -f urls.txt -d 3 -m 500 -o ./out

# 4. 运行测试（全离线）
python -m pytest tests -q

# 5. 发版门禁（10 项）
python tools/release_check.py
```

常用参数：`-d` 深度（`0` = 仅抓取种子）· `-m` 页数上限 · `-o` 输出目录 · `--strategy bfs|dfs|bff` · `--page-timeout` 单页超时（`0` = 关闭）· `--robots` 开启 robots.txt 合规。

**新增站点**（无需代码）：创建 `rules/sites/<域名>.yaml` → 通过 `python -m kiana_vnext_plus.cli rule-validate rules/sites/<域名>.yaml` 校验 → 使用 `rule-test <文件> --url <URL>` 试运行。

## 边界与诚实说明

已知限制在此明确列出，包括尚未解决的部分。

**能力边界**

- **支持公开页面的反爬对抗**：TLS 指纹模拟、真实浏览器回退、挑战求解、可选验证码服务平台接口 —— 这是核心能力，已在上方亮点①中说明。
- **不涉及账号权限**：登录墙、付费墙与账号权限内的内容，仅通过使用者自行提供的 cookie 访问；凭据不足时如实报告错误，不强行绕过。
- **不是框架、不是服务、不支持多用户。** 设计目标为单用户单机环境。
- **不采集个人信息**：联系方式、邮箱、IP 在落盘前即被脱敏。

**尚未做到的事（如实列出）**

- 部分平台的直链解析**仅在离线测试中验证过**，缺少针对实时服务的端到端证据。缺少登录态时采用诚实降级 —— 返回可读的错误原因，而非强行绕过。
- 少数实站解析目前失败，原因尚未定位，属未决项（不排除平台侧变更）。
- 安装包体积较大（约 542 MB）—— 浏览器二进制随包分发，以此换取"安装即可运行、无需联网下载运行时"。
- 覆盖率仅统计报告，不设强制阈值；LLM 相关能力默认关闭。

**概括**：它能稳定地采集公开可访问内容；它不是用于获取账号权限内或付费内容的工具。
