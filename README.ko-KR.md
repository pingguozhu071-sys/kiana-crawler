## 개요

Windows용 **단일 머신 수집 엔진**입니다. 자체 완결형 asyncio 크롤러 코어를 중심으로 구성하며, PySide6 데스크톱 인터페이스를 제어 화면으로 사용합니다.

설계는 사이트 지원 범위가 아니라 다음 네 가지 문제를 기준으로 구성했습니다.

| | 문제 | 접근 방식 |
|---|---|---|
| **수집** | 사이트마다 TLS 지문, JS 챌린지, 행동 탐지로 콘텐츠 접근을 제한합니다 | 5단 폴백: 프로토콜 → 스텔스 → TLS 전환 → 실제 브라우저 → 직결 |
| **파싱** | 사이트마다 마크업 구조가 다릅니다 | 범용 본문 추출 + 선언형 사이트 규칙 + 내장 JSON 파싱 |
| **데이터 품질** | 중복, 빈 페이지, 개인정보가 결과물에 포함될 수 있습니다 | 내용 지문 중복 제거 + 품질 게이트 + 3계층 마스킹 |
| **안정성** | 수십 개의 동시 요청, 수 시간 연속 실행, 응답이 멈추는 페이지 | 리스 + CAS 일관성 + 페이지별 감시 + 토큰 버킷 속도 제한 + 이어받기 다운로드 |

## 기술 하이라이트

각 하이라이트는 **문제 → 구현 → 주요 수치 → 해당 모듈**의 동일한 4부 구조를 따릅니다.

### ① 5단 폴백: 콘텐츠 도달성

> **문제**: 사이트마다 콘텐츠 접근을 제한하는 방식이 다릅니다. 어떤 사이트는 콘텐츠를 그대로 제공하고, 어떤 사이트는 TLS 핸드셰이크를 지문으로 식별하며, 어떤 사이트는 실제 JS 실행 이후에만 렌더링합니다. 단일 전략으로는 세 경우를 모두 처리할 수 없습니다.

- **구현**: 비용이 낮은 순서로 5단을 구성합니다 — 프로토콜(TLS 위장) → 스텔스 → TLS 전환 → 실제 브라우저 → 직결. 실패하거나 챌린지가 감지되면 요청을 다음 단으로 승격합니다. 저비용 경로가 성공하면 브라우저는 실행하지 않습니다.
- **주요 수치**: 5단 · 동시 코루틴 20~50개 · 브라우저 렌더링에는 별도 예산 상한 적용(브라우저 폭주 방지)
- **해당 모듈**: `engine_router.py`(스케줄링) · `protocol_engine.py` · `solver_engine.py`

### ② 플랫폼 리졸버: 미디어 직링크 추출

> **문제**: 미디어 사이트는 재생 가능한 URL을 내장 JSON에 보관하며, 서명이 적용되고 만료 시간이 있습니다. 페이지 URL을 범용 다운로더에 전달하면 최고 화질을 놓치는 경우가 많습니다.

- **구현**: 요청 파라미터를 구성하기 전에 **페이지에 이미 존재하는 데이터를 먼저 읽습니다**(`window.__INITIAL_STATE__`, JSON-LD). 플랫폼별 리졸버 4개는 모두 하나의 스키마(`MediaItem`: source / media_id / kind / streams / images / method)로 수렴하므로, 호출 측은 단일 필드만 참조합니다. 페이지 상태에서 추출한 URL은 사용 전에 SSRF 게이트로 다시 검사합니다.
- **주요 수치**: 리졸버 4개(Douyin / Xiaohongshu / Kuaishou / NetEase Cloud) · 통합 스키마 1개 · 추출된 모든 URL 재검사
- **해당 모듈**: `media_schema.py` · `*_resolver.py` · `universal_downloader.py`(테이블 기반 디스패치)

### ③ 리스 + CAS: 정확히 한 번 처리

> **문제**: 동시성 처리의 전형적인 결함 두 가지입니다 — 두 코루틴이 같은 페이지를 처리하거나(중복 내보내기), 다른 워커가 이미 작업을 가져간 뒤에 결과를 기록하는 경우(상태 손상)입니다.

- **구현**: 작업을 확보할 때 리스(`leased_at` / `lease_expires`)를 기록하고 60초 하트비트로 갱신합니다. **무엇을 저장하기 전에 워커는 CAS(compare-and-swap)를 획득해야 하며**, 실패하면 아무것도 기록하지 않습니다. 감시 장치와 실패 경로에는 "완료된 작업을 덮어쓰지 않음" 가드가 있습니다.
- **주요 수치**: 하트비트 60초 · 페이지별 감시 300초(설정 가능, 비활성화 가능) · CAS 3상태(획득 / 상실 / DB 오류)
- **해당 모듈**: `frontier.py` · `page_processor.py`

### ④ 감시 장치와 2단 속도 제한: 실행 안정성

> **문제**: 페이지 하나가 멈추면 배치 전체가 지연될 수 있습니다. 또한 단순한 속도 제한은 종료되지 않는 재시도 폭주로 이어집니다.

- **구현**: 제한 시간을 초과한 페이지는 종료하고 재시도 대상으로 표시하되, 같은 배치의 다른 페이지에 영향을 주지 않습니다. 속도 제한은 **2단 토큰 버킷**(전역 + 도메인별)입니다. 스로틀링은 **재시도 예산을 소비하지 않습니다** — 별도 카운터와 자체 데드레터 임계값을 사용하므로 메인 루프의 종료 조건에 실제로 도달할 수 있습니다.
- **주요 수치**: 감시 **300초**(일반 페이지 60초 미만, 5배 여유) · 도메인별 동시성 **20** · `Retry-After` 상한 **300초**
- **해당 모듈**: `crawler.py` · `rate_limiter.py` · `concurrency.py`

### ⑤ 재인코딩 없는 이어받기 다운로드

> **문제**: 대용량 다운로드가 중단되었을 때 처음부터 다시 받아서는 안 되며, 재인코딩은 원본 품질을 손상시킵니다.

- **구현**: 전체 크기와 Range 지원 여부를 먼저 확인한 뒤 → `.part` 파일로 스트리밍 → 정확한 바이트 오프셋에서 재개 → 바이트 수 검증 → **원자적 이름 변경** 순서로 처리하므로, 이후 단계에서 부분 파일이 관찰되지 않습니다. 영상은 재인코딩 없이 바이트 단위로 전송하고, 오디오는 오디오 채널이 활성화된 경우에만 MP3로 변환합니다. 서버가 Range를 지원하지 않으면 기존 `.part` 파일을 이어 붙이지 않고 폐기하여 손상된 파일이 생성되지 않도록 합니다.
- **주요 수치**: 바이트 수 검증 + 원자적 배치 · m3u8 프래그먼트 및 AES-128 복호화 지원 · ffmpeg는 **병합**에만 사용하며 재인코딩에는 사용하지 않음
- **해당 모듈**: `universal_downloader.py` · `m3u8_downloader.py` · `media_downloader.py`

### ⑥ 홉 단위 SSRF 게이트

> **문제**: **진입점 URL 검증만으로는 충분하지 않습니다.** 외부 이미지 URL이 내부 주소를 가리키는 302를 반환하면 기반 HTTP 라이브러리가 이를 그대로 따라가며, **내부 응답이 일반 이미지로 디스크에 기록됩니다.** 로컬 루프백 서비스 두 개로 재현했습니다.

- **구현**: 모든 외부 요청은 하나의 공용 프리미티브를 통과합니다 — 진입점에서 검증하고, 자동 리다이렉트를 비활성화한 뒤, **홉마다 따라가며 재검증**합니다. 호스트 이름을 먼저 정규화합니다(IPv6 존 ID와 마지막 점이 붙은 FQDN 모두 차단 목록을 우회하는 데 사용되었습니다). 사설망 판정은 표준 라이브러리가 누락한 대역까지 포함합니다. DNS 판정에는 90초 만료를 적용하여 "공인 주소로 해석한 뒤 내부 주소로 재지정"하는 리바인딩 기법을 차단합니다.
- **주요 수치**: 리다이렉트 상한 **10홉** · DNS 판정 TTL **90초** · 사설 주소 **25가지** 형태 대응 · 10진수 / 16진수 / 8진수 IP 표기도 처리
- **해당 모듈**: `url_utils.py`(저장소에서 참조가 가장 많은 모듈, fan-in) · 모든 다운로드 및 탐색 경로

### ⑦ 3계층 마스킹과 명시적 경계

> **문제**: URL 내 전화번호, 이메일, 토큰이 결과물에 유출되는 것은 실제 위험입니다. **마스킹에는 경계가 있습니다** — 잘못된 위치에 적용하면 기능이 즉시 손상됩니다.

- **구현**: 3계층으로 구성합니다 — 로깅(필터는 **handler**에 연결하며, root logger에 연결하면 아무 효과가 없습니다), 부수 경로(print 브리지, GUI 로그, 예외 출력), 산출물(내보내기 사본은 레코드 단위로 정제).
  **예외는 명시합니다**: 작업 큐의 URL은 *이후* 요청을 위한 키입니다. 서명 파라미터를 마스킹하면 재수집이 403으로 실패합니다. 이 판단 근거는 코드 주석에 기록하여 이후에 "친절한" 수정으로 깨지지 않도록 했습니다.
- **주요 수치**: 민감한 URL 파라미터 **19개** 유형 · 전화번호 / 이메일 / IP · 레코드 단위 깊이 6까지 재귀
- **해당 모듈**: `sanitizer.py` · `config.py`(배선) · `page_processor.py`(내보내기 사본)

### ⑧ 10개 항목 릴리스 게이트

> **문제**: 단일 유지보수자 프로젝트에서 릴리스가 깨지는 주된 원인은 검증되지 않은 가정입니다.

- **구현**: 명령 하나로 10개 항목을 검사하며, **하나라도 실패하면 릴리스가 차단됩니다**: 4개 파일 버전 일치 · git 작업 트리 정상 · 전체 테스트 스위트 · 정적 분석(기준선 고정, 하향만 허용) · 의존성 감사 · 비밀 정보 스캔 · 자격 증명 위생 · 규칙 및 자산 무결성 · 실사이트 다중 회귀 · 빌드 표면.
- **주요 수치**: 검사 **10개** · **오프라인 테스트 675개** · 정적 기준선은 현재 수치로 고정(하향만 허용)
- **해당 모듈**: `tools/release_check.py` · `.github/workflows/ci.yml` · `tests/`

## 아키텍처

```
launcher_v9.py          GUI 진입점(5페이지: 홈 / 로그 / 데이터 / 작업 / 설정)
  └ launcher_v8.py      활성 심볼 4개만 유지(엔진 브리지, 로그 브리지, 설정 경로, 키 보관)
run_crawler.py          명령줄 진입점 —— GUI에서는 프로세스 내 엔진으로도 동작합니다
  └ crawler.py          엔진 조립(7개 _init_* 가 배선표, run() 이 메인 루프)
      ├ engine_router.py      5단 폴백 스케줄링
      ├ page_processor.py     단일 페이지 파이프라인
      ├ frontier.py           SQLite 큐(리스 / CAS / 마이그레이션)
      └ url_utils.py          보안 프리미티브(참조 최다)
```

**페이지 하나의 처리 흐름**(17단계):

```
작업 디렉터리 생성 → 시드 분기 → 큐 적재 → 배치 가져오기(리스) → 출구 및 슬롯 확보 → 하트비트
  → 캐시 적중? → 5단 라우팅 → 파싱 폭탄 가드 → 마스킹 → 중복 제거 → 품질 게이트
  → CAS 확보 → 저장/내보내기 → 미디어 적재 → 링크 발견 → 통계
```

**실행 형태**: 단일 프로세스, asyncio 코루틴입니다. 스레드는 블로킹 호출을 위임하는 용도로만 사용하며 **멀티프로세싱은 사용하지 않습니다**. 엔진은 **자식 프로세스가 아닙니다**. GUI는 자체 이벤트 루프를 가진 데몬 스레드 안에서 엔진을 실행하고, `print`와 `logging`을 UI로 브리지합니다.

## 빠른 시작

**요구 사항**: Windows 10/11 x64 · Python ≥ 3.11

```bash
# 1. 의존성 설치(런타임 + 개발, 전부 버전 고정)
pip install -r kiana_vnext_plus/requirements.txt
pip install -r requirements-dev.txt

# 2. 데스크톱 UI 실행
python launcher_v9.py

# 3. 또는 명령줄에서 실행
python run_crawler.py "https://example.com" -d 0 -m 1 -o ./out
python run_crawler.py -f urls.txt -d 3 -m 500 -o ./out

# 4. 테스트 스위트 실행(오프라인)
python -m pytest tests -q

# 5. 릴리스 게이트 실행(10개 항목)
python tools/release_check.py
```

주요 옵션: `-d` 깊이(`0` = 시드만) · `-m` 페이지 수 상한 · `-o` 출력 디렉터리 · `--strategy bfs|dfs|bff` · `--page-timeout` 페이지별 제한 시간(`0` = 비활성) · `--robots` robots.txt 준수 활성화.

**사이트 추가**(코드 수정 없음): `rules/sites/<domain>.yaml`을 작성하고 → `python -m kiana_vnext_plus.cli rule-validate rules/sites/<domain>.yaml`로 검증 → `rule-test <file> --url <url>`로 드라이런합니다.

## 경계와 솔직한 설명

알려진 한계를 명시하며, 아직 해결되지 않은 항목도 포함합니다.

**실제 경계**

- **공개 페이지의 봇 차단 대응은 포함합니다**: TLS 위장, 실제 브라우저 폴백, 챌린지 해결, 선택적 캡차 해결 서비스 키를 지원합니다. 이는 핵심 기능이며 위 하이라이트 ①에 문서화되어 있고, 생략한 것이 아닙니다.
- **계정 권한은 다루지 않습니다**: 로그인 월, 유료 장벽, 계정 권한 범위의 콘텐츠는 *사용자가 제공한* cookie가 있을 때만 접근합니다. 그것으로 충분하지 않으면 강제로 우회하지 않고 읽을 수 있는 오류를 반환합니다.
- **프레임워크도 서비스도 다중 사용자 도구도 아닙니다.** 한 사람이 한 대의 컴퓨터에서 사용하는 것을 목표로 설계했습니다.
- **개인정보를 수집하지 않습니다.** 연락처, 이메일, IP는 기록되기 전에 마스킹됩니다.

**아직 지원하지 않는 항목(명시)**

- 일부 플랫폼 리졸버는 **오프라인 테스트로만 검증**되었으며, 실제 서비스에 대한 종단 간 검증 증거가 없습니다. 로그인 세션이 없으면 강제로 우회하지 않고 읽을 수 있는 사유를 반환합니다.
- 일부 실사이트 리졸버는 현재 실패합니다. 원인이 특정되지 않아 확정된 플랫폼 측 변경이 아니라 미해결 항목으로 남겨 두었습니다.
- 설치 파일이 큰 편(약 542 MB)입니다 — 브라우저 바이너리를 내장하여 런타임 추가 다운로드 없이 "설치 후 즉시 실행"을 선택했습니다.
- 커버리지는 보고하지만 임계값으로 강제하지 않습니다. LLM 보조 기능은 기본적으로 비활성화되어 있습니다.

**한 줄 요약**: 공개적으로 접근 가능한 콘텐츠를 안정적으로 수집하며, 계정 권한이나 결제 뒤의 콘텐츠에 접근하는 도구가 아닙니다.
